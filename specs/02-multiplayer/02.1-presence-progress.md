## Scope

Make participants visible to each other — names, avatars, milestones, connection —
without ever sharing card contents.

### Milestone reporting (`app/src/session/`)
- The sort store publishes milestones: on every keep/discard/undo/round change, send
  `reportProgress { round, sorted, kept, done }` — counts only, schema-enforced (00.2).
  Debounced 500ms trailing (decision; plan is silent) so a swipe burst sends one intent.
  `done: true` fires once when the participant reaches the result screen.
- Milestones flow through the 01.2 offline queue — sorting offline reports on resume.

### Roster UI (`app/src/components/Roster.tsx` + Avatar from 00.3)
- Visible in lobby and (collapsed to an avatar strip, expandable) during sort, wall:
  per participant — `Avatar` (deterministic `avatarHue`), display name, role tag for
  facilitator, progress line ("Round 2 · 14 sorted · 5 kept", or "Done ✓"), and a
  connection dot: filled = connected, hollow = disconnected (from `connected` in
  `SessionState`). Never card contents — the client only has counts anyway.
- Self is marked "(you)". Sorted by join order (record insertion order, decision).

### Lobby (`routes/sort` pre-start state)
- Before `startGame`, joined participants see the roster + "waiting to start" state;
  any participant may start a non-facilitated game, only the facilitator starts a
  facilitated one (decision, consistent with F9/peer mode). Config lock on start is
  already server-enforced (01.1).

### Gated round notice
- If `gate` is set and the participant's next round > `openRound`, the round-complete
  interstitial shows "Waiting for Round N to open" and Continue is disabled until a
  `patch` opens it (control UI is 03.4).

## Acceptance criteria
- [x] `reportProgress` debounce: a burst of 10 rapid keeps produces one intent with final
      counts (unit test with fake timers, `app/src/session/milestones.test.ts`).
- [x] **Invariant 1 (PRD §6.1, end-to-end):** two-browser E2E `e2e/presence.spec.ts`
      captures every WebSocket frame from both clients through join + full round pre-
      reveal and asserts no frame or roster render contains any card value/description;
      DO storage dump (dev endpoint or test hook) contains none either.
- [x] Two-browser E2E: B sees A appear in the roster on join, sees A's counts advance
      while A sorts, and sees A marked "Done ✓" at result screen.
- [x] Connection dot: killing A's socket flips A to disconnected on B's roster within
      5s; rejoin flips it back (`e2e/presence-connection.spec.ts`).
- [x] Avatar hue is identical for the same UUID across both browsers (E2E asserts
      matching computed style / data-hue attribute).
- [x] Gated round notice blocks Continue until a `setGate` patch opens the round
      (component test driving the store with a patch; control UI not required).
- [x] Offline-sorted progress arrives after reconnect (extends `e2e/reconnect.spec.ts`:
      counts on B eventually match A's offline sorting).
- [x] Roster is accessible: list semantics, names + status readable by screen reader
      (Testing Library role assertions).
- [x] `pnpm gate` green.
