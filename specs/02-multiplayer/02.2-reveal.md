## Scope

Opt-in, per-round, immutable reveal snapshots — the only moment card choices leave the
device.

### Client (`app/src/session/` + `routes/sort`)
- **Reveal prompt**: a gentle, dismissible prompt on the round-complete interstitial and
  the result screen ("Share your Round 2 result?"). Dismissal is per round, remembered
  in the sort store (decision). Never blocks progression.
- **First-time explainer**: before the first reveal ever in this browser, a `Modal`
  (00.3, focus-trapped) explains exactly what reveal shares (that round's kept cards +
  order, name) and what stays private. Shown once, flag in localStorage
  `vc:reveal-explainer-seen` (decision). Confirm proceeds to reveal.
- **Reveal action**: builds `RevealSnapshot { cards, ranked, revealedAt }` from local
  sort state — full card objects (`value`, `description`) so the wall/export need no
  deck lookup — and sends `reveal { round, snapshot }`.
- **Un-reveal**: on any round the participant has revealed, an "Un-reveal" action sends
  `unreveal { round }`; the snapshot disappears from `reveals` for everyone. Re-reveal
  afterwards creates a fresh snapshot.
- Revealed state is visible on the result screen/interstitial ("Shared ✓ · Un-reveal").

### Server (already largely in 00.2/01.1 — this spec proves it end-to-end)
- The DO (via `applyIntent`) rejects: snapshot card count ≠ round's numeric keep-count
  (or > N for keep-any round 1), reveal for an already-revealed (participant, round) key,
  reveal for a gated round, snapshot cards not in the session deck (decision: validate
  membership against `config.deck`). Rejections return `error` events surfaced as a
  `Toast`.

## Out of scope

- Export of revealed plaques → **04.1**.

## Acceptance criteria
- [ ] **Invariant 2 (PRD §6.2):** a second `reveal` for the same (participant, round)
      is rejected and state is byte-identical; `unreveal` deletes the key (never edits);
      reveal → unreveal → reveal yields the new snapshot — DO test
      `party/src/reveal.test.ts` + fast-check property from 00.2 stays green.
- [ ] **Invariant 3 (server half, PRD §6.3):** DO test sends snapshots with N-1, N+1,
      and off-deck cards → all rejected with typed error codes; exactly-N accepted.
- [ ] Explainer modal appears exactly once per browser before the first reveal, is
      focus-trapped, and its confirm proceeds to reveal (component test +
      `e2e/reveal.spec.ts`).
- [ ] Two-browser E2E `e2e/reveal.spec.ts`: A completes a round and reveals → B's
      session state gains A's snapshot (cards + order); before A reveals, B has only
      A's name/avatar/counts.
- [ ] Un-reveal E2E: A un-reveals → snapshot disappears from B's state; A re-reveals →
      it returns.
- [ ] Ranked reveal preserves order end-to-end (final-round reveal in E2E asserts
      card order on B matches A's ranking).
- [ ] Reveal rejection surfaces a Toast, and the client remains functional (component
      test feeding an `error` event).
- [ ] Reveal prompt is dismissible and never blocks Continue (component test).
- [ ] `pnpm gate` green.
