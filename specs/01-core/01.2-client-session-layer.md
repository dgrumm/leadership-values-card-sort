## Scope

The typed bridge between the SPA and the Session DO: `app/src/session/`.

### Socket hook (`app/src/session/useSession.ts`)
- One WebSocket per participant to `/api/session/:code/ws`. All outbound messages built
  by typed intent creators (`app/src/session/intents.ts`) that attach a fresh
  `intentId` (`crypto.randomUUID()`); all inbound parsed with `EventSchema` — parse
  failure logs and drops, never crashes the app.
- Exposes `{ state: SessionState | null, connection, send }`; server `state`/`patch`
  events reduce into a session Zustand store created per `(code)` via factory
  (`app/src/session/createSessionStore.ts`) — no module-level global store.

### Connection state machine
`connecting → live → reconnecting → resumed | expired` (architecture §5), implemented as
an explicit reducer with unit tests:
- Socket close/error in `live` → `reconnecting`; exponential backoff (0.5s → 8s cap,
  jitter, decision) reconnect attempts.
- On reopen: send `rejoin(token)`; on full `state` event → `resumed` (then `live`).
- `error{code:'expired'|'not_found'}` → `expired` (terminal; UI directs to landing).
- Quiet **connection pill** component (`app/src/session/ConnectionPill.tsx`): nothing in
  `live`, "Reconnecting…" pill in `reconnecting`, tokens-only styling.

### Tokens & rejoin (`app/src/session/tokens.ts`)
- `participantToken` + participant UUID stored in localStorage keyed
  `vc:<code>:token` on join; presented on every rejoin. Same-browser revisit of a
  session URL silently resumes (no name prompt). Clearing storage → normal join.

### Reconnect replay
- Intents sent while not `live` are queued (in-memory, FIFO); after `resumed`, the queue
  flushes in order. Duplicates are safe by DO idempotency; the full-state resync
  overwrites any stale local session state (no client reconciliation).

### Join UI (minimal)
- `routes/join`: code + display name form → `join` intent, stores token, navigates to
  the (placeholder until 01.3) sort route. Landing "Join a game" links here;
  `/join/:code` pre-fills the code. Full create flow is 03.1 — until then a dev-only
  "quick create" button calls `POST /api/session` with the classic template.

## Out of scope
- Sort UI and local sort persistence → **01.3**. Roster/presence rendering → **02.1**.
- Facilitator creator-token UX → **03.1**/**03.4**. Nudge/gate/spotlight senders exist
  as typed creators but have no UI until their owning specs.

## Acceptance criteria
- [x] State machine unit tests cover every transition above, including
      close-during-connecting and expired-during-reconnecting
      (`app/src/session/connection.test.ts`).
- [x] Join flow E2E: enter code + name → roster contains self in received `state`
      (`e2e/join.spec.ts` against `wrangler dev`).
- [x] **Invariant 4 (membership half, PRD §6.4):** E2E `e2e/rejoin.spec.ts` — join,
      reload the page: session resumes silently with the same participant UUID, no
      re-join form shown.
- [x] Socket-kill E2E: force-close the socket (CDP or dev hook); pill shows
      "Reconnecting…", then disappears after automatic rejoin; a queued intent sent
      while offline is delivered exactly once after resume
      (`e2e/reconnect.spec.ts` asserts via resulting state).
- [x] Malformed inbound event is dropped without crashing (unit test feeds garbage to
      the event handler — `app/src/session/useSession.test.ts`'s `parseInboundMessage`
      tests).
- [x] No Cloudflare/API secrets in the client bundle: token secret never referenced from
      `app/` (grep test in `app/src/session/tokens.test.ts` CI-level assertion +
      `pnpm token:lint` unaffected).
- [x] Session store is factory-created per session code; no exported singleton store
      (unit test constructs two isolated stores).
- [x] `pnpm gate` green.
