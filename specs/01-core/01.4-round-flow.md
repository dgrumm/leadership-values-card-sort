## Scope

Everything between "queue empty" and "final result", driven by `shared/` engine
functions — trim and rank are conditional phases of the same flow, not pages.

### Round completion (`routes/sort` + store)
- On empty queue, call `canFinishRound(sortState, roundCfg)`:
  - `{ ok }` → round-complete interstitial (round name, kept count) → **Continue**
    advances via `nextRound()` — kept cards become the next round's queue, reshuffled
    (seed = participantId + new round); discards animate to a **discard stack** whose
    counter accumulates across rounds (e.g. "37 set aside").
  - `{ needTrim: n }` → **TrimGrid**.
  - Keeping fewer than N is allowed — Continue is enabled whenever kept ≤ N and the
    queue is empty.

### TrimGrid (`app/src/engine-ui/TrimGrid.tsx`)
- Kept cards as a responsive grid of GameCards (`sm`); tap/Enter toggles a card as cut
  (visual dim + ✂ badge, announced); header counts down "Cut 3 more". Confirm enabled
  exactly at ≤ N; cut cards join `discarded`. Fully keyboard operable (roving
  tabindex, decision), 44px targets.

### RankBoard (`app/src/engine-ui/RankBoard.tsx`) — final round only, if
`rounds[last].rank === true`
- After the final round reaches its keep-count: drag-to-order list of the final cards
  using `@dnd-kit/core` + sortable, **keyboard sensor configured** (space to lift,
  arrows to move, space to drop — dnd-kit defaults), announcements via dnd-kit
  `announcements`. Order stored in `sortState.ranking`. Confirm → result screen.

### Result screen (`routes/sort` terminal state)
- The participant's final cards (ordered if ranked) as a local plaque preview —
  name, game title, cards in theme. This is local-only; reveal (02.2), wall (02.3) and
  export (04.1) build on it. Placeholder "Reveal" and "Download" buttons disabled with
  "coming soon" tooltips (decision), so the layout is final.
- Client-side keep-count enforcement: the sort UI never allows finishing with
  kept > N past TrimGrid (Invariant 3, client half).

## Out of scope

- Export rendering → **04.1**. Round gating UX → **03.4** (a gated locked-round notice

## Acceptance criteria
- [ ] `canFinishRound`/`nextRound` wiring unit-tested through the store: over-limit →
      trim; at/under limit → advance; discard counter accumulates across rounds
      (`app/src/stores/round-flow.test.ts`).
- [ ] **Invariant 3 (client half, PRD §6.3):** it is impossible to reach the next round
      with kept > keep-count — store test attempts to force it; TrimGrid Confirm stays
      disabled until ≤ N (component test).
- [ ] TrimGrid: cut/uncut by pointer and keyboard, countdown text correct, confirm moves
      cut cards to discarded (`app/src/engine-ui/trim-grid.test.tsx`).
- [ ] RankBoard reorders by pointer drag and by keyboard sensor alone; final order lands
      in `ranking` (`app/src/engine-ui/rank-board.test.tsx`).
- [ ] Refresh during trim and during rank restores that exact phase and selection
      (E2E `e2e/round-flow-refresh.spec.ts`).
- [ ] Full solo journey E2E, desktop + mobile viewports: dev-12 deck, rounds 12 → keep 8
      → keep 3 (ranked): sort → trim (deliberately over-keep) → next round → rank →
      result screen shows 3 ordered cards (`e2e/solo-journey.spec.ts`).
- [ ] Keyboard-only solo journey passes (same spec, keyboard project).
- [ ] Ranking round-trips: result screen order matches RankBoard order after refresh.
- [ ] `pnpm gate` green.
