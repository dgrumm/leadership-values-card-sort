## Scope

The single writer: one Durable Object per session in `party/`, hosting the `shared/`
reducer. Milestone 1 is a minimal echo session (socket connect → echo) to de-risk the
DO/Workers toolchain; then the real logic.

### Worker routes (`party/src/index.ts`)
- `POST /api/session` — body `{ config?: GameConfig }` (defaults to the classic template).
  Generates a 6-char code (`/^[A-Z0-9]{6}$/`, unambiguous alphabet without `0/O/1/I`,
  retry on collision), initializes the DO (id = code), returns
  `{ code, creatorToken }`. `creatorToken` = HMAC-signed facilitator credential.
- `GET /api/health` (kept from 00.1). Export route belongs to 04.1.
- WebSocket upgrade `GET /api/session/:code/ws` → forwarded to the DO. Uses the
  **WebSocket hibernation API**.

### `SessionServer` DO (`party/src/session.ts`)
- Holds `SessionState` (schema from 00.2); every inbound message Zod-parsed
  (`IntentSchema`); invalid → `error` event, socket stays open.
- Delegates all mutations to `applyIntent` from `shared/` — the DO adds only transport,
  auth, persistence, and expiry:
  - **join**: issues participant UUID + `participantToken` (UUID + HMAC over
    `code:uuid` with a Worker secret, decision: `SESSION_TOKEN_SECRET` via wrangler
    secret / `.dev.vars`); derives `avatarHue` from UUID (hash → 0–359); role =
    facilitator iff `creatorToken` presented. Duplicate display names allowed.
  - **rejoin(token)**: verifies HMAC, marks `connected: true`, replies with a full
    `state` event (reconnect = resync; no event replay).
  - All other intents require a valid `participantToken`.
- **Idempotency**: duplicate `intentId` per participant (bounded LRU in state, cap 64)
  produces no state change and no broadcast.
- **Persistence**: `ctx.storage.put('state', …)` checkpoint after every accepted
  mutation; state lazily loaded on wake (hibernation-safe).
- **Broadcast**: accepted mutations emit `patch` events to all sockets; `state` on
  join/rejoin. Socket close → `connected: false` patch (no roster removal).
- **Expiry**: alarm at `createdAt + 24h` → `storage.deleteAll()`; connected sockets get
  `error{code:'expired'}` and are closed. Joining an expired/unknown code →
  `error{code:'not_found'}`.
- Phase transitions per architecture §8: `lobby` (joinable, `updateConfig` allowed) →
  `active` on `startGame` (config locked) → `concluded` on `conclude`. Join allowed in
  lobby and active; late joiners see current `gate`.

### Tests (`party/src/*.test.ts`, Vitest + `@cloudflare/vitest-pool-workers`)
Join/rejoin flow, token verification, idempotent replay, config lock, gating rejection,
checkpoint/restore across DO restart, alarm expiry purge.

## Acceptance criteria
- [ ] `POST /api/session` returns a valid unique code and `creatorToken`; created DO
      serves `state` over WebSocket (`party/src/session.test.ts`).
- [ ] Join issues UUID + HMAC `participantToken`; a tampered token is rejected with
      `error{code:'auth'}` (test).
- [ ] Two participants named "Dave Smith" coexist with distinct UUIDs and avatarHues (test).
- [ ] **Invariant 5 (PRD §6.5):** re-sending the same intent (same `intentId`) N times
      changes state once and broadcasts once — DO-level test
      `party/src/idempotency.test.ts` asserts storage checksum and broadcast count.
- [ ] Rejoin with a valid token returns a full `state` snapshot and flips
      `connected: true`; membership survives a simulated DO eviction + wake
      (checkpoint/restore test).
- [ ] `updateConfig` accepted in `lobby`, rejected in `active` (config-lock test).
- [ ] `reveal` for a round above `gate.openRound` is rejected server-side (test).
- [ ] Alarm at +24h purges all storage; subsequent connect → `error{code:'not_found'}`
      (test using `vitest-pool-workers` alarm advance).
- [ ] No card contents appear in any stored or broadcast data before a reveal —
      DO test drives a full pre-reveal flow and asserts serialized storage/events
      contain no deck card values (Invariant 1, server half).
- [ ] `pnpm gate` green.
