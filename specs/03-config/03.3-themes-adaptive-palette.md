## Scope

Session theming: designed variants plus an adaptive palette extracted from uploaded
card-back art — always within the token system, always WCAG AA.

**This is the accent layer, and it composes over a pack.** 00.6 owns the *aesthetic* —
surface treatment, canvas, field, type, shadow language, base palette — as a build-time
pack. This spec owns what varies *per session*: the accent triplet and the card-back art.
A variant never redefines surface/ink; it overrides the accent triplet within whatever pack
is active, and every pairing is validated against **that pack's** surface/ink rather than
against tactile-warm's.

### Theme model (`shared/src/schemas/config.ts`, extends 00.2 stub)
- `ThemeConfigSchema`:
  `{ variant: 'default' | 'sage' | 'indigo' | 'custom', accent: PaletteTriplet,
  cardBackArt?: { dataUrl: string } }` where `PaletteTriplet` =
  `{ accent, accentHover, accentSubtle, onAccent }` as OKLCH strings. Three designed
  variants (names/values decided in this spec, recorded in
  `app/src/theme/variants.ts`) override only the accent triplet + card-back art;
  **surface/ink come from the active pack (00.6), never from the variant.** Stored in
  `config.theme` so every client and the export renderer resolve identical tokens.
  `config.theme` carries no pack field — the pack is build-time by 00.6's decision, so this
  schema is unchanged in shape from the 00.2 stub apart from the accent triplet.

### Contrast math (`shared/src/color/`)
- Pure, unit-tested: OKLCH ⇄ sRGB conversion, WCAG 2.1 relative-luminance contrast
  ratio, `deriveTriplet(accent)` (hover/subtle/on-accent in OKLCH), and
  `validatePalette(triplet, surface, ink)` returning pass/fail per pairing. `surface`/`ink`
  are parameters precisely so the same math validates against any pack — including a dark
  one, where the accent that passed on light paper may not. Derivation must not assume the
  surface is lighter than the ink.
  (on-accent/accent ≥ 4.5:1; accent vs surface ≥ 3:1 for UI components; full pairing
  list in code).

### Art upload & extraction (`app/src/theme/palette-extraction.ts`, client-side)
- Upload PNG/JPG ≤ 1MB; client downscales via canvas to ≤ 256px before any use
  (architecture §12); stored as data URL in `config.theme.cardBackArt`.
- Extraction: sample downscaled pixels → cluster to dominant swatches (small built-in
  k-means/median-cut — decision: no heavyweight dependency) → rank candidates by
  chroma × coverage → `deriveTriplet` → `validatePalette`; first passing candidate
  wins. **No candidate passes → fall back to the default accent triplet** with a
  gentle notice ("We kept the classic palette so text stays readable") — the art is
  still used as card-back regardless.

### ThemeProvider (`app/src/theme/ThemeProvider.tsx`)
- Resolves `config.theme` to CSS custom-property overrides on a scope element (sets
  `--color-accent*` vars only — components untouched, token lint still passes). Applies
  to sort, wall, plaques, exports (04.1 reads the same `config.theme`).

### Designer integration (`routes/create` theme section, stub from 03.1)
- Variant swatches + art-upload dropzone with live preview: GameCard back + a sample
  plaque re-render in the candidate palette; the fallback notice appears when
  extraction fails validation.

## Out of scope
- Export-side token resolution → **04.1** (consumes `config.theme`).
- Base tokens/primitives → **00.3**. Facilitator panel → **03.4**.
- **The aesthetic itself → 00.6.** Surface treatment, canvas, field, type, shadow language
  and the base palette are the pack's; this spec must not add a pack, retune one, or make the
  pack selectable per session.

## Acceptance criteria
- [ ] Contrast math unit tests against known WCAG reference pairs (e.g. #777/#fff =
      4.47:1 fails AA) (`shared/src/color/contrast.test.ts`).
- [ ] **Invariant 6 (PRD §6.6):** fast-check property — for arbitrary uploaded-art
      swatch sets, the resulting `config.theme.accent` triplet always passes
      `validatePalette`, or equals the default triplet
      (`shared/src/color/adaptive-palette.property.test.ts`).
- [ ] All three designed variants pass `validatePalette` **against every pack in
      `app/src/theme/packs/`** (unit test over `variants.ts` × packs) — a variant that only
      works on light paper is not shippable.
- [ ] Extraction fixtures: a vivid image yields a non-default AA-passing triplet; a
      near-monochrome low-contrast image falls back to default with the notice
      (unit tests with canvas-mocked fixtures + E2E `e2e/theme.spec.ts` uploading both
      fixture images).
- [ ] Upload >1MB is rejected client-side with a message; accepted art is downscaled
      to ≤256px before storage (unit test asserts data-URL dimensions).
- [ ] Theme travels: creator picks a variant/uploads art → second browser's lobby,
      sort cards, and wall plaques render the same accent (two-browser E2E asserts
      computed `--color-accent` matches).
- [ ] `pnpm token:lint` still passes — ThemeProvider is the only runtime writer of
      color vars, and it lives in `app/src/theme/`.
- [ ] Serialized config with max art stays within the 128KB storage-value budget
      (unit test, consistent with 03.2).
- [ ] `pnpm gate` green.
