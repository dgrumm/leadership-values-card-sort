## Scope

The create flow: from landing "Start a game" to a shareable session, template-first
with a full designer behind it. Replaces the 01.2 dev-only quick-create.

### Create route (`routes/create`)
- **Template picker**: the default template *Leadership Values — 40 → 8 → 3* (Leadership
  40 deck, rounds: "Open triage" keep-any → "Top 8" → "Top 3" ranked; matches PRD §4.1)
  with one-tap **Create game**, plus **Customize** opening the designer. (Only the one
  bundled template in 2.0 — decision; saved templates are 2.1.)
- **Round editor**: add/remove rounds (1–6); per round: name (text), keep-count (number
  input, or "keep any" toggle available only on round 1), ranking toggle on the final
  round only. Live validation via `validateConfig` — violations (non-decreasing keeps,
  keep > deck size, etc.) render inline messages mapped from the 00.2 error codes;
  Create disabled while invalid.
- **Deck picker**: the three bundled decks with card count + preview of first cards;
  selection re-validates keep-counts against deck size. (Custom CSV entry point renders
  here but is implemented in **03.2**; theme section likewise stubs to **03.3**'s
  default variant.)
- **Facilitation toggle**: on = creator is facilitator (F9 features); off = peer mode.
- **Game title**: text field, default from template (decision: defaults to deck name +
  "Sort").

### Create → lobby handoff
- Create calls `POST /api/session` with the validated `GameConfig`; stores
  `creatorToken` (localStorage `vc:<code>:creator`, decision) and joins as the first
  participant. Post-create screen shows the **6-char code** large + a copyable share
  link `/join/:code`.
- **Late config edits**: while phase is `lobby`, the creator can reopen the designer;
  changes go via `updateConfig` and broadcast to joined participants' lobby view.
  People can join during configuration; `startGame` locks config (server-enforced
  since 01.1) and the designer becomes read-only.

## Out of scope
- CSV paste/upload + validation UI → **03.2**.
- Theme variants, art upload, adaptive palette → **03.3**.
- Facilitator in-game panel → **03.4**.

## Acceptance criteria
- [ ] One-tap path E2E `e2e/create.spec.ts`: landing → Start → default template →
      Create → code + share link shown; second browser joins with the code and sees the
      classic config in its lobby.
- [ ] Round editor enforces all `validateConfig` rules inline with Create disabled:
      component tests cover non-decreasing keeps, keep > deck size, >6 rounds,
      keep-any off round 1, rank off final round
      (`app/src/routes/create/round-editor.test.tsx`).
- [ ] Switching to a smaller deck flags now-invalid keep-counts immediately
      (component test).
- [ ] Lobby `updateConfig` E2E: creator edits rounds while B sits in the lobby → B's
      lobby reflects the change; after `startGame` the designer is read-only and
      `updateConfig` is rejected (already server-tested in 01.1; E2E asserts the UI).
- [ ] Facilitation toggle results in `role: 'facilitator'` for the creator in roster
      (E2E asserts role tag).
- [ ] Share link `/join/:code` pre-fills the code (E2E).
- [ ] Designer is fully keyboard operable; all controls labelled (Testing Library
      role/name assertions).
- [ ] `pnpm gate` green.
