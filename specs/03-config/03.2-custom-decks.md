## Scope

Bring-your-own deck: CSV in, validated deck in the session config. Entirely in-browser
until `updateConfig`/create carries the deck to the DO.

### CSV input (`routes/create` deck section)
- **Paste** (textarea) and **file upload** (`.csv`, `<input type="file">`) paths, both
  feeding the same parser. Format: `value,description` with optional header row
  (detected case-insensitively, decision). Parser: **papaparse** (decision — plan names
  only "CSV upload"; papaparse handles quoting/BOM; ~7KB gzip acceptable) wrapped in
  `app/src/routes/create/parse-deck-csv.ts` returning `Result<Deck, DeckCsvError[]>`.
- Validation = `DeckSchema` (00.2) plus designer-context rule: card count ≥ the
  config's largest keep-count. Errors are **instant** (on paste/upload) and precise:
  row-numbered messages ("Row 12: duplicate value 'Integrity'", "Row 3: empty
  description"), aggregate counts, and a hard stop past 100 cards.
- On success: preview (deck name field — default from file name or "Custom deck",
  decision — card count, first 6 cards as mini GameCards) and **Use this deck**, which
  sets `config.deck` (full deck JSON travels inside `GameConfig`; DO re-validates via
  schema on `updateConfig`/create — no separate upload endpoint, decision per
  architecture: config over code, one writer).

### Round-editor integration
- Largest-keep vs deck-size validation reruns when either side changes (shared logic
  with 03.1's editor). Removing a custom deck reverts to the previously selected
  bundled deck.

### Limits
- Per-session storage budget: a deck of 100 max-length cards must keep serialized
  `GameConfig` under 128KB (DO storage value limit) — asserted in a unit test
  (architecture §12 risk).

## Out of scope
- Card-back art upload and palette → **03.3**.
- Cross-session deck library / sharing → 2.1 (PRD §9).
- Authoring-time CSV→JSON script for bundled decks → done in **00.2**.

## Acceptance criteria
- [x] Parser unit tests (`parse-deck-csv.test.ts`): happy path with/without header;
      quoted fields with commas; CRLF + BOM; duplicate values (case-insensitive);
      empty descriptions; blank lines skipped; 101 cards rejected; each error carries
      a row number.
- [x] Paste and file-upload paths produce identical results for the same bytes
      (component test).
- [x] Deck with fewer cards than the largest keep-count is rejected with a message
      naming both numbers (component test).
- [x] Valid CSV shows preview + count; **Use this deck** puts the deck into the config
      and the round editor re-validates against its size (component test).
- [x] E2E `e2e/custom-deck.spec.ts`: create a game by pasting a 12-card CSV, start,
      and sort the first card — the sorted card's value comes from the pasted CSV;
      a second browser joining sees the custom deck name in the lobby.
- [x] DO rejects a config whose deck violates `DeckSchema` even if the client is
      bypassed (party test posting an invalid deck to `POST /api/session`).
- [x] 100-card max-length deck keeps serialized config < 128KB (unit test). This is now a
      true ceiling: 00.2 was amended (approved 2026-08-15) to bound card text at
      `CARD_VALUE_MAX`/`CARD_DESCRIPTION_MAX`, and the test builds the largest deck the
      schema can represent at all. Card text over either bound gets a row-numbered CSV
      error naming the actual length.
- [x] Custom decks carry `source: 'custom'`; the designer branches on `source`, not on the
      deck name, so a custom deck named after a bundled one is still treated as custom
      (00.2 amendment, `parse-deck-csv.test.ts` + `deck.test.ts`)
- [x] Error list is announced to screen readers (`role="alert"`) and the textarea/upload
      controls are labelled (component test). Used `role="alert"` alone, matching 03.1's
      round-editor pattern, instead of adding `aria-live` on top (redundant with alert's
      implicit assertive live region).
- [x] `pnpm gate` green.
