## Scope

Prove the PRD §7 success criteria on the assembled product. This spec adds tests,
budgets, and fixes fallout — no new features.

### Two-browser E2E suite (`e2e/multiplayer/`)
- The canonical journey as one suite: create (facilitated, classic template) → two
  joins → sort both → reveal both → wall → spotlight → conclude → export — desktop +
  mobile viewport pairings. Consolidates/extends the per-spec E2Es into a single
  always-run flow (`e2e/multiplayer/journey.spec.ts`).

### Socket-kill reconnect E2E (`e2e/multiplayer/reconnect-60s.spec.ts`)
- Mid-sort, sever participant A's socket for 60s (CDP network conditions or route
  abort) while A keeps sorting. Assert: sorting never blocks; on restore, silent
  rejoin, milestones catch up on B, no duplicate roster entry, no lost decisions
  (PRD §7 "kill the network for 60s: no lost work, silent recovery").

### Load pass (`e2e/load/twelve.spec.ts` or a scripted harness `scripts/load-test.ts`)
- 12 participants (Playwright browser contexts or lightweight ws clients using the
  shared intent schema — decision: ws clients for the 12, one real browser observing)
  join one session, sort with realistic pacing, all reveal. Assert: every reveal lands,
  roster/wall consistent on the observing browser, no dropped patches, and per-session
  DO storage stays within budget (asserted via a test/dev endpoint).

### Known fallout to close (carried from earlier specs)
- **`concluded` is only half-enforced server-side.** 02.3 added a `concluded` guard to
  `setSpotlight` in `shared/src/engine/apply-intent.ts` (so a concluded session's wall is
  genuinely read-only, per tenet 1), but `reveal`/`unreveal` still have no such guard —
  only `join` and `setSpotlight` do. It isn't reachable through the UI (on `conclude`,
  `routes/Sort.tsx` redirects everyone to the wall), so it was left out of 02.3's scope
  rather than widening that spec. Close it here: guard `reveal`/`unreveal` on
  `state.phase === 'concluded'` and add engine unit tests, so "concluded ⇒ read-only" is
  a whole-state property rather than a per-intent accident.
- **No WebKit coverage in CI.** `playwright.config.ts` ships only `desktop-chromium` and
  `mobile-chromium`, so Safari and iOS — a real share of participants — are never exercised
  by the suite. 01.5 hit this concretely: its card flip puts `backdrop-filter` inside a
  `transform-style: preserve-3d` context alongside `backface-visibility: hidden`, which
  WebKit has historically flattened, and Chromium cannot answer whether it does. That spec
  verified WebKit by hand (`pnpm check:webkit`, `scripts/webkit-flip-check.mjs`) because a
  spec-shaped check would have joined every gate run with no project to run under, and
  adding a third engine to the whole suite was beyond its scope. Close it here: add a
  `desktop-webkit` project (plus `mobile-safari` if the suite stays fast enough), fix the
  fallout, and fold `webkit-flip-check.mjs`'s assertions into the regular specs so the
  standalone script can be deleted. Budget for real failures: no spec has ever run on WebKit.

### Accessibility audit
- Lighthouse a11y ≥ 95 on: landing, create, join, lobby, sort (mid-round), trim, rank,
  result, wall (grid + spotlight) — automated via `@axe-core/playwright` on each screen
  (zero serious/critical violations) plus Lighthouse CI runs recorded in the PR
  (decision: axe gates CI; Lighthouse evidence attached, both ≥95).
- Keyboard-only full journey E2E: create → join → sort → trim → rank → reveal → wall →
  export without a single pointer event (`e2e/multiplayer/keyboard-journey.spec.ts`).

### Perf budget
- Budgets (decision, recorded in `scripts/perf-budget.mjs`, gate-enforced): initial app
  JS ≤ 250KB gzip; landing LCP < 2.5s on Playwright mobile emulation; sort-route
  route-level code-splitting verified (designer/wall chunks not loaded to sort).
- Art/deck limits re-asserted end-to-end: 1MB art + 100-card deck session stays under
  the DO storage budget.

## Out of scope
- New product features of any kind. Deployment automation (Pages/Workers deploy
  workflow) — added here only if trivial; otherwise a follow-up spec.

## Acceptance criteria
- [ ] `journey.spec.ts` passes on desktop and mobile projects in CI.
- [ ] `reconnect-60s.spec.ts` passes: zero lost decisions, silent recovery, single
      roster entry.
- [ ] Load pass: 12 participants complete and reveal; observer wall shows 12 plaques;
      storage budget assertion green.
- [ ] `concluded` is read-only for every mutating intent, not just `setSpotlight` —
      `reveal`/`unreveal` rejected on a concluded session, with engine unit tests.
- [ ] A WebKit project runs in CI and the suite is green on it. 01.5's card-flip compositing
      assertions live in `e2e/sort-flip.spec.ts` rather than a hand-run script, and
      `scripts/webkit-flip-check.mjs` plus its `pnpm check:webkit` entry are deleted.
- [ ] axe: zero serious/critical violations on all listed screens
      (`e2e/a11y.spec.ts`); Lighthouse a11y ≥ 95 evidence attached to the PR.
- [ ] `keyboard-journey.spec.ts` completes the full journey with keyboard only.
- [ ] Perf budget script green in `pnpm gate`; budgets committed.
- [ ] Full `pnpm gate` + entire Playwright suite green in CI on the PR.
- [ ] All six PRD §6 invariant tests (00.2, 01.1, 01.2/01.3, 02.2, 03.3) still green in
      this final assembly — `pnpm spec:status` shows every other spec `done`.
