## Scope

The keepable artifact: server-rendered PNG/PDF plaques, identical to the wall, plus the
shareable results link.

### Export route (`party/src/export.ts`)
- `GET /api/export/:code/:participantId/:round.png` and `….pdf` on the Worker:
  1. Fetch the reveal snapshot + `config.theme` + game title from the Session DO
     (internal DO fetch). **Only revealed data is reachable by construction** — the
     route reads exclusively from `state.reveals`; unknown code / participant / round /
     un-revealed round → 404.
  2. Render the shared plaque layout (02.3 `plaque-layout.ts` — imported, not
     duplicated) as JSX → **satori** → SVG → **resvg** (`@resvg/resvg-wasm`,
     decision: wasm build for Workers) → PNG at 2× (1200px wide, decision).
  3. PDF: embed the PNG in a single-page **pdf-lib** document sized to the plaque
     (decision: raster-embed, not vector, keeps parity trivial).
- Fonts: Fraunces woff/ttf subsets bundled as Worker assets for satori (same family as
  00.3). Theme tokens resolved from `config.theme` exactly as ThemeProvider does —
  shared resolver in `shared/` or `plaque-layout.ts` (decision: move token resolution
  helper into the shared layout module so client and Worker use one code path).
- Response headers: correct `Content-Type`, `Content-Disposition: attachment;
  filename="<name>-<game>-round<N>.png"` (slugified), `Cache-Control: private,
  max-age=300` (decision).

### Client integration
- **Download PNG** / **Download PDF** buttons (enabled at last) on the result screen
  (own plaque, once revealed — export requires a reveal; the disabled state explains
  "Reveal to enable download", decision consistent with Invariant 1) and on every wall
  plaque (any revealed plaque is downloadable by anyone in the session, decision —
  revealed data is shared data).
- **Session results link**: the wall URL `/wall/:code` presented as a copyable
  "Results link" on the wall and result screens; a small note states it expires with
  the session (24h).

## Out of scope
- Plaque visual design/layout → owned by **02.3** (this spec consumes it).
- Load/perf validation of export under concurrency → **04.2**.

## Acceptance criteria
- [ ] Party test `party/src/export.test.ts`: PNG route returns `image/png` with
      plausible dimensions; PDF returns a parseable single-page `application/pdf`
      (pdf-lib re-open) for a revealed (participant, round).
- [ ] Privacy: export of an un-revealed round, unknown participant, or unknown session
      returns 404 with no body leakage; after `unreveal`, a previously working export
      URL returns 404 (party test).
- [ ] Parity: satori render of the fixture snapshot matches the wall plaque — E2E
      `e2e/export.spec.ts` screenshots the wall plaque and compares structure/labels;
      a snapshot test pins the satori SVG output for a fixture (theme + ranked cards).
- [ ] Themed export: with a custom accent in `config.theme`, the exported SVG/PNG
      contains the custom accent color, not the default (party test inspects SVG).
- [ ] Ranked snapshots render order badges in the export (SVG snapshot).
- [ ] E2E: reveal → click Download PNG → browser download event yields a non-empty
      `.png` with the expected filename; same for PDF.
- [ ] Result-screen download buttons are disabled pre-reveal with explanatory tooltip
      (component test).
- [ ] Results link on the wall copies `/wall/:code` and works in a fresh browser
      context until expiry (E2E).
- [ ] No export path can read local (unrevealed) sort state — the route has no such
      input by construction; test asserts route reads only DO `reveals`.
- [ ] `pnpm gate` green.
