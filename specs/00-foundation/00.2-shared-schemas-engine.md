## Scope

`shared/` becomes the single source of truth for contracts and rules. Pure TS, no I/O.

### Zod schemas (`shared/src/schemas/`)
- `deck.ts` — `CardSchema` `{ value: string, description: string }`;
  `DeckSchema` `{ name: string, cards: Card[] }` with refinements: unique card values
  (case-insensitive), non-empty descriptions, 1–100 cards.
- `config.ts` — `RoundConfigSchema` `{ name: string, keep: number | 'any', rank: boolean }`
  (`keep: 'any'` allowed only in round 1; `rank: true` allowed only on the final round);
  `GameConfigSchema` `{ title: string, deck: Deck, rounds: RoundConfig[], theme: ThemeConfig,
  facilitated: boolean }` with refinements: 1–6 rounds, numeric keep-counts strictly
  decreasing, every keep-count ≤ deck size. `ThemeConfigSchema` here is minimal
  (`{ variant: string }`) — extended by 03.3.
- `session.ts` — `SessionStateSchema` exactly as architecture §4.1: `code` (`/^[A-Z0-9]{6}$/`),
  `config`, `phase: 'lobby'|'active'|'concluded'`, `participants` record keyed by UUID
  (`name`, `avatarHue`, `role: 'facilitator'|'participant'`, `connected`,
  `progress: { round, sorted, kept, done }`), `reveals: Record<Uuid, Record<number,
  RevealSnapshot>>`, `spotlight: Uuid | null`, `gate: { openRound: number } | null`, plus
  `processedIntents: Record<Uuid, string[]>` (bounded LRU, cap 64 per participant — kept in
  state so the reducer is pure and idempotency is property-testable).
  `RevealSnapshotSchema` `{ cards: Card[], ranked: boolean, revealedAt: number }`.
- `messages.ts` — `IntentSchema`: discriminated union on `type`, every variant carrying
  `intentId: uuid` and (except `join`) `participantId: uuid`:
  `join, rejoin, updateConfig, startGame, reportProgress, reveal, unreveal, nudge,
  setGate, setSpotlight, conclude`. `reveal` carries `{ round: number, snapshot:
  RevealSnapshot }`; `reportProgress` carries only `{ round, sorted, kept, done }` — the
  schema has no field that can hold card data. `EventSchema`: `state` (full snapshot),
  `patch` (targeted update), `nudge { text }`, `error { code, message }`.

### Game engine (`shared/src/engine/`)
- `validateConfig(config): Result` — wraps schema + refinements with typed error codes.
- `shuffle(cards, seed)` — seeded Fisher–Yates (per-participant shuffle needs determinism
  in tests; decision: seed = participantId + round).
- `nextRound(sortState, config): SortState` — kept cards become next round's queue,
  reshuffled; discard counter accumulates.
- `canFinishRound(sortState, roundCfg): { ok: true } | { needTrim: n } | { incomplete }`.
- `applyIntent(sessionState, intent): { state, events } | { rejection }` — the DO reducer.
  Enforces: replayed `intentId` → unchanged state and no events; `updateConfig` only in
  lobby; `startGame` locks config; reveal snapshot card count must equal the round's
  numeric keep-count (≤ for `'any'`); reveal keys are write-once (`unreveal` deletes,
  re-reveal after unreveal is allowed as a new snapshot); reveal into a round above
  `gate.openRound` rejected; `setGate`/`nudge`/`setSpotlight`-of-others require
  facilitator role; spotlight of own plaque allowed for participants.

### Bundled decks (`decks/`)
- `decks/leadership-40.json`, `decks/extended-72.json`, `decks/dev-12.json` (card content
  recovered from v1 git history, tag `v1-final`); each validated against `DeckSchema` in
  `decks/decks.test.ts`. Finish `decks/scripts/csv-to-json.ts` (reads `value,description`
  CSV → validated deck JSON).

### Property tests (Vitest + fast-check, `shared/src/engine/*.property.test.ts`)
Random sequences of valid + invalid intents against `applyIntent` must never violate:
write-once reveals; kept-count constraints; duplicate-`intentId` idempotency; no event
ever contains card values for an unrevealed (participant, round).

## Acceptance criteria
- [ ] All schemas exported from `shared` with inferred TS types; `tsc --noEmit` strict passes.
- [ ] `validateConfig` rejects: non-decreasing keeps, keep > deck size, 0 or >6 rounds,
      `'any'` outside round 1, `rank` outside final round (unit tests name each case in
      `shared/src/engine/validate-config.test.ts`).
- [ ] `DeckSchema` rejects duplicate names, empty descriptions, 0 and 101 cards
      (`shared/src/schemas/deck.test.ts`).
- [ ] The classic template (Leadership 40 → 8 → 3, ranked final) round-trips through
      `GameConfigSchema` and `validateConfig` (fixture test).
- [ ] `applyIntent` unit tests cover every intent type's accept and reject paths
      (`shared/src/engine/apply-intent.test.ts`).
- [ ] fast-check property suite proves, over random intent sequences: write-once reveals,
      server-side keep-count enforcement, duplicate-intent no-op, no unrevealed card data
      in any emitted event (`shared/src/engine/invariants.property.test.ts`).
- [ ] `reportProgress`/`Event` schemas structurally cannot carry card contents
      (test asserts parse failure when card fields are smuggled in).
- [ ] Three bundled decks parse against `DeckSchema`; `csv-to-json` converts a fixture
      CSV to a valid deck (`decks/decks.test.ts`, `decks/scripts/csv-to-json.test.ts`).
- [ ] `pnpm gate` green.
