## Scope

00.4 introduced the liquid-glass look but applied it only to the sort-flow primitives
(`GameCard`, `Sheet`, `Modal`, `KeptTray`, `TrimGrid`). Every other screen — the create
flow, the designer, the lobby, rosters, form fields, toasts — stayed on the opaque
`bg-surface-raised` panels from 00.3, so those screens read as "unthemed" on the
iridescent field. A design system must cover the whole experience, not a subset of screens.

This spec makes glass a **system**: define the glass surface treatment **once**, then apply
it to every panel/surface across the app. No app surface is left on bare
`bg-surface-raised` where a themed surface is intended. Legibility is still guaranteed by
keeping text on the near-opaque `--color-glass-strong` fill (AA already asserted in 00.4);
this spec only widens coverage and does not change the field, the tokens' values, the card
sizing, or the per-session theming model (03.3 still layers on top).

### One glass surface, defined once (`app/src/theme/`)
- Define the glass surface treatment in a single place — a `.glass-panel` utility class in
  the theme CSS (a `@layer components` rule composing the existing 00.4 tokens:
  `--color-glass`/`--color-glass-strong` fill, `backdrop-filter: blur(var(--glass-blur))`,
  `--color-glass-edge` hairline border, `--shadow-glass`), plus a `.glass-panel-strong`
  variant for text-bearing panels (uses `--color-glass-strong`). No new color/blur/shadow
  values — compose 00.4's tokens. This class is the single definition every screen uses;
  screens must NOT hand-assemble the glass look from raw utilities (that's what fragmented
  in 00.4).
- If any new composited pairing is introduced (text over a glass variant not already
  covered), extend `tokens.test.ts`'s AA assertions to include it. Text-bearing surfaces use
  the `-strong` variant so `--color-ink`/`--color-ink-muted` keep ≥ 4.5:1 (worst case already
  proven in 00.4).

### Apply the surface everywhere (compose the class; don't re-skin per screen)
Replace opaque `bg-surface-raised` panels with the glass surface across every remaining
surface, keeping the 00.3 tokens for spacing/radius/text:
- Create flow: `routes/Create.tsx` (template summary section), `routes/create/deck-picker.tsx`
  (deck option cards), `routes/create/round-editor.tsx` (round panels + inputs),
  `routes/create/designer.tsx`.
- `routes/lobby.tsx` (panel, share-link field, roster rows).
- `components/Roster.tsx`, `components/Toast.tsx`.
- Text inputs app-wide (currently `bg-surface-raised`): a glass field style (may be the
  `-strong` variant) so form fields match the system while keeping input contrast.
- Route `<main>` elements stay transparent (00.4/#53) so the field shows behind everything.

### Out of scope
- Per-session accent variants / adaptive palette → **03.3** (layers on this base).
- The export/plaque renderer stays opaque `--color-surface` — no `backdrop-filter` in
  satori/resvg (→ **04.1**). Do not glass-ify export surfaces.
- Changing the glass *intensity* (blur radius / panel opacity) or the iris field itself —
  those token values are 00.4's; this spec is coverage, not re-tuning.

## Acceptance criteria
- [ ] A single glass surface definition exists in `app/src/theme/` (`.glass-panel` /
      `.glass-panel-strong`), composing only existing 00.4 tokens; `pnpm token:lint` passes
      (no raw glass/blur/hex outside `theme/`).
- [ ] No app surface renders on bare `bg-surface-raised`: a test (unit or grep-style check)
      asserts `bg-surface-raised` no longer appears in `app/src/routes/**` or
      `app/src/components/{Roster,Toast}.tsx` — those compose the glass class instead.
- [ ] `tokens.test.ts` AA assertions still pass, extended to any new text-on-glass pairing
      introduced; `--color-ink`/`--color-ink-muted` ≥ 4.5:1 on every text-bearing glass
      surface.
- [ ] E2E screenshot review: `/create` and a lobby both render glass panels on the
      iridescent field (not opaque white) at 1440px and 390px — panels are translucent
      (their computed `backdrop-filter` is a blur, not `none`).
- [ ] Keyboard focus still uses the `--shadow-focus` glow app-wide (a11y gate); no screen
      regresses to a hard outline.
- [ ] `pnpm gate` green.
