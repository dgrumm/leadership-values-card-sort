## Scope

00.4 and 00.5 built one aesthetic — tactile-warm liquid glass — and wired it in by name.
`.glass-panel` is used at 29 sites across 14 files, the iridescent field is hardcoded in
`tokens.css`, `--shadow-*` assumes dark ink on light paper, and `tokens.test.ts` asserts AA
against light-paper pairings specifically. The look is good; the problem is that *changing*
it means editing every one of those sites, and "we might want a different aesthetic" is a
standing requirement, not a hypothetical.

This spec makes the aesthetic a **swappable unit** — a *pack* — and ships a second one
(Aurora) to prove the seam is real. A pack is a named set of custom-property **values**;
component classes stay fixed and aesthetic-neutral. Swapping the app's entire look becomes
changing one constant.

**A pack is build-time, not per-session.** The active pack is a typed constant in
`app/src/theme/packs/`. This deliberately keeps `ThemeConfigSchema` untouched, ships only the
active pack's font to the client and to 04.1's satori bundle, and leaves the per-session
accent/adaptive-palette model to 03.3 unchanged. If facilitator-selectable packs are ever
wanted, the constant is promoted into config — contained, because the pack is already a
named, typed unit.

### The two layers (why this is not 03.3)
- **Pack** (this spec) — surface treatment, canvas, field, motion, type, shadow language,
  base palette. Few, curated, authored in code.
- **Accent** (03.3) — the accent triplet plus card-back art, per session, possibly derived
  from uploaded art. Composes *over* whichever pack is active.

Validation composes: `pack base × accent → validatePalette`. 03.3's property test is
unchanged in intent; it gains the active pack's surface/ink as its input rather than
assuming tactile-warm.

### Aesthetic-neutral primitives (`app/src/theme/`)
- Rename the surface classes so the name does not encode one aesthetic:
  `.glass-panel` → `.panel`, `.glass-panel-strong` → `.panel-strong`, `.scrim` stays
  `.scrim`. Mechanical rename across all 29 call sites (14 files under `app/src`, plus
  `e2e/glass-coverage.spec.ts` → rename to `e2e/surface-coverage.spec.ts`).
- Every visual decision inside those classes becomes a pack-supplied variable, so the class
  bodies are identical across packs:
  `--panel-bg`, `--panel-blur`, `--panel-border`, `--panel-shadow`, `--scrim-bg`,
  `--scrim-blur`. "Aurora has no glass" is then `--panel-blur: 0px`, not a code change.
- The following existing tokens move from fixed values to pack-supplied, because a dark
  canvas invalidates all of them: `--color-surface`, `--color-surface-raised`,
  `--color-ink`, `--color-ink-muted`, `--color-accent*`, `--color-on-accent`,
  `--shadow-card`, `--shadow-card-lifted`, `--shadow-sheet`, `--shadow-glass` (→
  `--shadow-panel`), `--shadow-focus`, the `--color-iris-*` field stops, and
  `--glass-blur` (→ `--panel-blur`).
- Structural tokens stay in `tokens.css` and are **not** pack-controlled: spacing, radius,
  z-index, the type *scale* (rung sizes/leading), durations, easings. A pack changes how the
  app looks, not how it is measured.

### Pack definition (`app/src/theme/packs/`)
- `packs/<name>.ts` exports a typed `Pack` — the var→value record plus metadata (display and
  body font family, whether the field animates, the avatar swatch lightness/chroma). One
  TypeScript source of truth so the AA tests and the CSS both read the same values.
- `packs/<name>.css` sets those vars on `:root` and `@import`s only that pack's font.
- `packs/index.ts` exports `ACTIVE_PACK` and the `PackName` union. `tokens.css` imports the
  active pack's CSS. Only the active pack's font enters the bundle.
- Two packs ship: **`tactile-warm`** (the current look, a behavioral no-op) and **`aurora`**.

### The field is a pack property
- The body field becomes `--field-*` stops plus a pack flag for whether it animates.
- **Every pack sets it to not animate.** The current 28s infinite 5-stop drift across the
  whole canvas is an animated mesh-gradient on the entire page — a named anti-pattern, and
  no genre permits it (the most permissive caps at two blooms, fixed-attached, no
  animation). `tactile-warm` keeps its five stops as a static gradient; the
  `prefers-reduced-motion` branch in `tokens.css` becomes redundant for the field and is
  removed with it.
- `e2e/reduced-motion.spec.ts` currently asserts the field *drifts* when motion is allowed.
  That assertion inverts: the field is static in both cases. Do not delete the test —
  retarget it, so the reduced-motion contract stays covered by the GameCard flip assertions
  it also holds.

### Aurora pack
Per the atmospheric genre: dark canvas, one warm accent hue, **no glassmorphism**, fade-only
motion, up to two fixed radial blooms at ~20–30% footprint, elevation by lightness rather
than shadow, no hairlines. Display face **Geist Sans** (`@fontsource/geist-sans`,
self-hosted — a third-party font request fails
`e2e/reduced-motion.spec.ts`'s no-external-requests assertion), tight display tracking.
- Where the genre's page-level guidance conflicts with app chrome, app chrome wins: Aurora's
  structure row calls for typographic-only buttons, but this is a multiplayer tool with real
  controls, so CTAs stay accent-filled pills per the genre's own allowance. Button *voice*
  is a page-level axis; this spec ships an app.
- Aurora must satisfy every gate tactile-warm satisfies — it is not exempt for being second.

### Per-pack contrast validation
- `tokens.test.ts` becomes pack-parameterized: every AA pairing is asserted **for each pack**
  in `packs/`, reading values from the TS pack definition. A pack that fails AA fails the
  build. This is product invariant 6, and it is the gate that makes adding a pack safe.
- `Avatar.tsx` computes `oklch(55% 0.12 <hue>)` at runtime from participant data with
  `text-on-accent` on top — the one place a color is not a token, so it cannot be validated
  statically. Its lightness/chroma become pack-supplied, and a test asserts the avatar
  swatch passes AA against that pack's `--color-on-accent` **across the full hue wheel**,
  not one sample.

### The coverage gate, generalized
`glass-coverage.test.ts` asserts "no bare `bg-surface-raised`" — a rule about one aesthetic's
escape hatch. Replace it with the pack-agnostic invariant it was reaching for: **nothing
outside `app/src/theme/` may hand-assemble a surface** (compose fill + blur + border +
shadow itself) instead of composing `.panel`/`.panel-strong`/`.scrim`. Keep the existing
allowlist-with-reasons and its stale-exemption guard; `Plaque.tsx`'s exemption stays
architectural (04.1 renders it through satori, which cannot do `backdrop-filter`).

## Out of scope
- **Per-session accent / adaptive palette → 03.3.** This spec gives 03.3 a pack base to
  compose over; it does not implement accent selection, art upload, or extraction.
- **`ThemeConfigSchema` / any `shared/` contract change.** The pack is build-time by
  decision. No DO, intent, or schema changes.
- **Per-route structure.** The centred full-viewport hero and the ten near-identical
  `min-h-screen flex-col items-center` screens are real findings, but they are layout, not
  tokens — structure is not themeable and a pack must not carry layout hints. Separate
  follow-up. (Expect Aurora to make the monotony *more* visible: a dark canvas is less
  forgiving than pastel.)
- **Retuning tactile-warm.** Apart from freezing the field animation, `tactile-warm` must
  render identically before and after. Taste changes to it are a different spec.
- **Export-side pack resolution → 04.1**, which reads the active pack's tokens and bundles
  its font for satori.

## Acceptance criteria
- [ ] `.glass-panel`/`.glass-panel-strong` no longer exist; all 29 call sites compose
      `.panel`/`.panel-strong`/`.scrim`. No aesthetic word (`glass`, `aurora`) appears in a
      class name under `app/src` outside `theme/packs/`.
- [ ] Two packs exist under `app/src/theme/packs/` with a shared typed shape; `ACTIVE_PACK`
      is the single switch. A unit test asserts every pack supplies every var the primitives
      consume — a pack missing one fails the build rather than rendering an unset value.
- [ ] **Behavioral no-op for `tactile-warm`:** with `ACTIVE_PACK = 'tactile-warm'`, the full
      pre-existing suite passes unchanged except the two field-animation assertions, and a
      screenshot pass over Landing / Sort / lobby / wall / KitchenSink at 1440px and 390px
      shows no visual diff beyond the now-static field.
- [ ] **Invariant 6, per pack:** `tokens.test.ts` runs every AA pairing across every pack in
      `packs/`, reading the TS definitions; both packs pass. Includes text on
      `--panel-bg`/`--panel-strong` composited over every field stop of that pack.
- [ ] Avatar swatch passes AA against its pack's `--color-on-accent` across the full hue
      wheel (0–360 stepped), for every pack.
- [ ] `--shadow-focus` is legible on every pack's canvas — the current value hardcodes a
      white inner ring that vanishes on dark. A test or computed-style E2E assertion covers
      the focus ring's contrast against the active pack's surface at ≥ 3:1.
- [ ] With `ACTIVE_PACK = 'aurora'`: no `backdrop-filter` blur on any panel (the inverse of
      00.5's assertion — the same computed-style E2E, parameterized by pack), dark canvas,
      at most two fixed radial blooms, no field animation.
- [ ] Only the active pack's font is bundled: a build-output assertion (or E2E request
      check) shows Geist Sans absent under `tactile-warm` and Fraunces absent under
      `aurora`. No third-party font requests in either pack.
- [ ] The generalized surface-composition gate replaces the `bg-surface-raised` scan, keeps
      the allowlist-with-reasons plus its stale-exemption guard, and fails on a hand-rolled
      surface added anywhere outside `theme/`.
- [ ] `e2e/reduced-motion.spec.ts`'s field-drift assertions are retargeted (not deleted) to
      "field is static in both branches"; the GameCard flip reduced-motion contract stays
      asserted.
- [ ] `pnpm token:lint` passes — pack values live in `theme/packs/`, so raw color literals
      stay inside `theme/`.
- [ ] `pnpm gate` green under **both** packs (CI runs the suite twice, or the pack is
      parameterized in the test run).
