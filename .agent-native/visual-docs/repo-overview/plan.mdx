# Values Cards 2.0 — Repo Visual Docs

A local, repo-backed visual documentation layer for the v2 rebuild. The MDX lives in
this repo, comments stay beside it in `comments.json`, and the Plan UI reads it through
the localhost bridge — nothing is published.

These docs cover the load-bearing surfaces only: the wire contract, the single-writer
reducer, session state, and the client-side privacy boundary. UI component docs are
deliberately thin until a component's contract stabilizes.

Manifest: `../../../agent-native.json`

<Callout id="privacy-boundary" tone="decision">

**Tenet 2, privacy by architecture.** Unrevealed card choices never leave the device.
`createSortStore` holds `queue` / `kept` / `discarded` / `cut` / `ranking` in
localStorage only; the only card data that ever crosses the wire is a `reveal` intent's
`snapshot`. The server cannot leak what it never receives — which is why
`reportProgress` sends *counts* (`sorted`, `kept`) and never card identities.

</Callout>

### Worker routes

Three routes total. Everything gameplay-related rides the WebSocket; the HTTP surface only
mints sessions.

<Endpoint id="post-session" method="POST" path="/api/session" summary="Create a session" params={[
  {
    "name": "config",
    "in": "body",
    "type": "GameConfig",
    "description": "Optional. Omitted means CLASSIC_TEMPLATE."
  }
]} request={{
  "contentType": "application/json",
  "example": "{ \"config\": { \"title\": \"Leadership Values\", \"rounds\": [] } }"
}} responses={[
  {
    "status": "200",
    "description": "Created",
    "example": "{ \"code\": \"K3P9WQ\", \"creatorToken\": \"<hmac>\" }"
  },
  {
    "status": "400",
    "description": "invalid config — GameConfigSchema rejected the body"
  }
]}>

Retries up to `MAX_CODE_ATTEMPTS` (5) random 6-char codes, calling the DO's
`/internal/init` until one is unclaimed. `creatorToken` is an HMAC over the code and is
the *only* source of the facilitator role.

</Endpoint>

<Endpoint id="ws-session" method="GET" path="/api/session/{code}/ws" summary="Session WebSocket (upgrade)" auth="participantToken in each intent envelope; creatorToken on join" responses={[
  {
    "status": "101",
    "description": "Switching protocols"
  },
  {
    "status": "1008",
    "description": "Closed — not_found (unknown/expired code) or expired (24h alarm fired)"
  }
]}>

One socket per participant. Inbound frames are intents; outbound are `welcome`,
`state`, `patch`, `nudge`, and `error`. The DO runs with `hibernate: true`.

</Endpoint>

<Endpoint id="dump-session" method="GET" path="/api/session/{code}/dump" summary="Read-only state dump (dev/e2e only)" deprecated={true} responses={[
  {
    "status": "200",
    "description": "Full persisted SessionState"
  },
  {
    "status": "404",
    "description": "Not found — route does not exist unless DEV_STATE_DUMP === 'true'"
  }
]}>

Gated on the `DEV_STATE_DUMP` binding, which only `wrangler dev` and the e2e harness set.
It exists so the privacy E2E can assert invariant 1 against the DO's *actual persisted
storage* rather than the events it happened to broadcast. Unauthenticated, so it must
stay unset in production — a 6-char code would otherwise expose every participant UUID,
name, role, and progress.

</Endpoint>

### Session state

`SessionState` is what the DO persists under the `state` key and what a reconnecting
client receives whole (tenet 6). Records are keyed by opaque participant UUID; display
names are labels only (tenet 3).

`GameConfigSchema` enforces cross-round rules its per-round schema cannot see, each with a
stable `params.code`: `INVALID_ROUND_COUNT` (1-6 rounds), `ANY_OUTSIDE_FIRST_ROUND`,
`RANK_OUTSIDE_FINAL_ROUND`, `KEEP_EXCEEDS_DECK_SIZE`, and
`KEEP_NOT_STRICTLY_DECREASING`. That last one is what makes 40 → 8 → 3 valid and
40 → 8 → 8 not.

### Client connection

`useSession` owns one WebSocket per participant, the reconnect-with-backoff loop, and a
FIFO offline intent queue that flushes when the socket returns to `live`. Two details
that are easy to regress:

- **Epoch counter, not a boolean.** A discarded socket's `close` event is asynchronous and
  can land after the next effect run has already reset a shared flag. `epochRef` lets a
  superseded run recognize its own close and skip the reconnect — this is what keeps React
  StrictMode's dev mount/cleanup/remount from opening a second socket.
- **Malformed frames are dropped, never thrown.** `parseInboundMessage` tries
  `WelcomeSchema` first (transport/auth, outside `EventSchema`), then `EventSchema`, and
  returns `null` otherwise, so a hostile or buggy peer cannot crash the app.

### Review and agent handoff

Comment on any section, diagram, spec, or table in the local Plan UI. Agent-targeted
comments are the queue for a coding agent to change the repo and then patch these MDX
files, so the visual docs and the executable code stay in sync.

Freshness policy from the manifest: the three `shared/src/schemas/*` targets are
`required-on-pr` — a PR that changes the wire contract should update the data model and
authority table above. Everything else is `seed`.
